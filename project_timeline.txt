PHASE 6: ALPHA RELEASE & DUAL-LAYER RAM CACHING (August 12 - 13, 2026)
--------------------------------------------------------------------------------
* August 12 - 13, 2026 [Commits b59b391, 18a4583, 14f9655, 98b535a, c97700c, 6961a88, f45ba50, 24e4d5c, da8498c, 6b78a92]:
  - WHAT: Implemented dual-layer in-memory RAM caching for pre-synthesized tones
    (g_cpp_ram_cache), added static C++ DLL linking (-static-libgcc -static-libstdc++),

    and bundled the distribution package builder (build_distribution_package.py).
  - Released version tags: Prealpha_v1.5.0, Prealpha_v1.5.1, Prealpha_v1.5.2, and Alpha_v1.0.0.

PHASE 8: THE GREAT RUST MIGRATION (October 12, 2026 - Prealpha_v1.7.0)
--------------------------------------------------------------------------------
* October 12, 2026 [Commit 90ca839]:
  - WHAT: Completely migrated the Python / Tkinter front end to a 100% native Rust
    application (openorgelsynth.exe) built with eframe/egui, cpal, midir, and midly.
  - WHY: Python's Global Interpreter Lock (GIL) and Tkinter's sluggish single-threaded
    event loop caused UI stutter, random audio dropouts during window moves, high memory
    consumption (~400 MB RAM), and slow 4-second cold starts.
  - HOW:
    1. Built an immediate-mode GPU-accelerated console in rust/src/app.rs rendering at 60 FPS.
    2. Embedded openorgelsynth.cpp directly via rust/build.rs (cc::Build) and safe FFI (rust/src/ffi.rs).
    3. Created a dedicated real-time audio thread using cpal WASAPI output (rust/src/audio.rs).
    4. Achieved 1:1 feature parity: 30 stops, master volume, A4 tuning selector (415-466 Hz),
       pitch-class resonance wheel visualizer, Arduino USB serial console link (serial.rs),
       and 1-9 registration presets with Shift+Key saving.
    5. Dropped RAM footprint from 400 MB to 25 MB and cold startup time to <50 ms.

PHASE 11: NON-BLOCKING RE-SYNTHESIS & FALLBACK BLEED ELIMINATION (October 12, 2026 - Prealpha_v1.7.3 & v1.7.4)
--------------------------------------------------------------------------------
* October 12, 2026 [Commits 916aebf & b6a81c4]:
  - WHAT:
    1. Eliminated mid-song playback freezing during stop registration changes.
    2. Completely eradicated a phantom C++ single-harmonic flue fallback pipe that played
       when no stops were drawn and bled underneath soloed SoundFont playback.
    3. Added strict "No selected stops!" refusal guard and 1024-sample timeline cross-fading.
  - WHY:
    1. Changing stops while playing triggered render_midi_offline under engine.soundfont.lock(),
       starving the audio thread of samples and causing jarring 3-second audio pauses.
    2. In openorgelsynth.cpp line 606, a historical fallback synthesized a raw single-harmonic
       sine flute whenever num_stops == 0. When playing SoundFonts with no Principal Organ stops,
       this C++ pipe synthesized at raw amplitude ~2.0, causing the master normalizer to crush
       the SoundFont audio into near-silence.
    3. Clearing all stops mid-playback caused that fallback flue pipe to keep playing instead of silence.
  - HOW:
    1. Created SoundFontOfflineSnapshot: cloned active presets under lock in 0.005 ms and
       released the mutex immediately so the audio thread never blocks.
    2. Modified ToneBank::summed_tone and live_tone to output pure zeros (silence) when stops is empty.
    3. Added swap_audio with 1024-sample cross-fade for seamless, pop-free timeline transitions.
    4. Added has_any_active_stops() check in app.rs and render_midi: displays red warning toast
       "No selected stops! Please draw at least one stop before playing" and rejects playback/export.

PHASE 13: MAJOR MILESTONE v2.0.0 - 100% NATIVE RUST WAVETABLE & FM SYNTHESIS (October 12, 2026 - Prealpha_v2.0.0)
--------------------------------------------------------------------------------
* October 12, 2026 [Commit c6c1ebb]:
  - WHAT: Completely deprecated the legacy C++ DLL (openorgelsynth.cpp / openorgelsynth.dll)
    and FFI bridge, replacing it with a 100% native Rust DSP engine featuring 2048-sample
    bandlimited Wavetables and 2-Op/4-Op Frequency Modulation (FM) reed operators.
  - WHY:
    1. The legacy C++ additive loop evaluated 360 trigonometric sin() calculations per sample.
       For a 3-minute polyphonic piece, this required over 4.6 billion evaluations, creating
       severe CPU bottlenecks and rendering delays.
    2. Modeling complex acoustic reeds (Bombarde, Trombone, Trumpet, Clarinet, Oboe) with static
       additive harmonics produced flat, sterile tones without authentic reed tongue strike dynamics.
    3. External MinGW/g++ toolchain dependencies complicated compilation and executable distribution.
  - HOW:
    1. Wavetable Engine (rust/src/dsp/wavetable.rs): Pre-bakes harmonic spectra into 2048-sample
       periodic tables with power-of-two mask indexing (phase & 2047) and linear interpolation.
       Harmonics approaching Nyquist (sample_rate / 2) are automatically bandlimited. Delivers a
       100x+ synthesis speedup.
    2. FM Reed Engine (rust/src/dsp/fm.rs): Phase modulation operator pairs:
       y(t) = sin(w_c * t + beta(t) * sin(w_m * t + alpha * y_m(t-1))).
       Dynamic modulation index beta(t) transiently spikes during pipe attack (shallot strike chiff)
       and settles to steady-state brilliance. Ratio 1:2 configured for hollow Clarinets; 0.5:1.0
       with heavy feedback drive for brassy Bombarde/Bassoon growl.
    3. Native Reverberator (rust/src/dsp/reverb.rs): Pure safe Rust Schroeder-Moorer reverberator
       with 4 parallel Comb filters and 2 series All-pass filters.
    4. Embedded Samples (rust/src/dsp/stops_dsp.rs): Embedded clarion.wav and stoppedflue.wav decoded
       via hound, providing native pitch-interpolated looping for acoustic ranks 24-29.
    5. Clean Build: Removed cc::Build and C++ compilation from rust/build.rs. The entire project
       now compiles in seconds straight from cargo build --release with zero C++ dependencies!
